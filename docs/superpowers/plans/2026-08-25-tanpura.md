# Tanpura Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a synthesized tanpura drone — a continuous 4-string plucked-string pattern tuned to the user's calibrated Sa — and route it to speaker/headphone output without it ever touching the microphone capture path that feeds pitch detection.

**Architecture:** Each string is a `KarplusStrongString` (the standard plucked-string synthesis algorithm: a noise burst circulating through a damped delay line, whose length sets the pitch and whose damping sets the decay). `TanpuraSynth` owns 4 of these, cycles through a pluck pattern (Pa-Sa-Sa-Sa or Ma-Sa-Sa-Sa, tuned relative to the calibrated Sa) at a slow tempo, and mixes whichever strings are still ringing. `TanpuraAudioSource` wraps that as a `juce::AudioSource` so it plugs into JUCE's audio graph like any other playback source, with lock-free gain/enable/retune controls safe to call from the UI thread while `getNextAudioBlock()` runs on the audio thread. `MainComponent` mixes it into the output — and, since this is the first time this app has any audio *output* at all, the wiring must account for a real JUCE subtlety: with fewer input channels than output channels, `AudioSourcePlayer` aliases the callback buffer's first channel onto the *same memory* as the first output channel, pre-filled with a copy of the mic input — so the mic must be read out before anything overwrites that buffer, or the raw mic signal gets echoed straight back out to the speakers.

**Tech Stack:** C++17, JUCE 8.0.7 (`juce_audio_basics` for `AudioSource`/`AudioSourceChannelInfo`, already-linked `juce_audio_utils` for `MainComponent`), `juce::UnitTestRunner`.

## Global Constraints

- C++17. Test framework is `juce::UnitTestRunner`.
- **No licensing dependency**: the tanpura sound is synthesized, not sampled — no audio files are bundled or redistributed, sidestepping the licensing blocking-gate `TODOS.md` flagged for a sample-based approach.
- `TanpuraAudioSource`'s gain/enabled/retune controls must be safe to call from the UI (message) thread while `getNextAudioBlock()` runs on the audio thread, without a `CriticalSection` on the hot path — use lock-free atomics, following the same pattern already established in `CrepePitchEngine`'s atomic `status`.
- `MainComponent::getNextAudioBlock()` MUST read the mic channel out and hand it to `PitchWorker::pushAudio()` BEFORE writing any tanpura output into the buffer — see the Architecture note above. Get this backwards and the app either loses mic capture correctness or echoes the mic straight back out to the speakers.
- Must not regress the 49 existing tests.

```cpp
// src/audio/tanpura/KarplusStrongString.h
#pragma once
#include <vector>

// A single plucked-string voice using the Karplus-Strong algorithm: a burst
// of noise circulates through a damped delay line. The delay line's length
// (sampleRate / frequencyHz) sets the fundamental pitch; the damping factor
// applied each pass sets how quickly the string decays to silence.
class KarplusStrongString
{
public:
    void pluck (float frequencyHz, double sampleRateIn, float amplitude = 1.0f);
    float renderNextSample();
    bool isRinging() const;

private:
    static constexpr float kDamping = 0.996f;
    static constexpr int kMaxRingSamples = 44100 * 4; // ~4s upper bound - real decay is usually faster

    std::vector<float> delayLine;
    size_t readPos = 0;
    int samplesSincePluck = 0;
    bool ringing = false;
};
```

```cpp
// src/audio/tanpura/KarplusStrongString.cpp
#include "KarplusStrongString.h"
#include <cmath>
#include <cstdlib>

void KarplusStrongString::pluck (float frequencyHz, double sampleRateIn, float amplitude)
{
    const int delayLineLength = juce::jmax (2, (int) std::lround (sampleRateIn / (double) frequencyHz));
    delayLine.assign ((size_t) delayLineLength, 0.0f);

    for (auto& sample : delayLine)
        sample = amplitude * (2.0f * ((float) std::rand() / (float) RAND_MAX) - 1.0f);

    readPos = 0;
    samplesSincePluck = 0;
    ringing = true;
}

float KarplusStrongString::renderNextSample()
{
    if (! ringing || delayLine.empty())
        return 0.0f;

    const float out = delayLine[readPos];
    const size_t nextPos = (readPos + 1) % delayLine.size();

    delayLine[readPos] = kDamping * 0.5f * (delayLine[readPos] + delayLine[nextPos]);
    readPos = nextPos;

    if (++samplesSincePluck >= kMaxRingSamples)
        ringing = false;

    return out;
}

bool KarplusStrongString::isRinging() const
{
    return ringing;
}
```

```cpp
// src/audio/tanpura/TanpuraSynth.h
#pragma once
#include "KarplusStrongString.h"
#include <array>

enum class TanpuraTuning { PaSaSaSa, MaSaSaSa };

// Cycles a 4-string Karplus-Strong pattern tuned relative to the given Sa.
// PaSaSaSa: Pa (mandra, -500 cents), Sa (mandra, -1200 cents), Sa (madhya,
// 0 cents), Sa (madhya, 0 cents) - the standard tuning for Pa-emphasizing
// ragas. MaSaSaSa substitutes a Ma (mandra, -700 cents) for the Pa string,
// for Ma-emphasizing ragas. Cents follow this codebase's existing
// convention (see SwarMapper.h): Sa=0, Ma=500, Pa=700.
class TanpuraSynth
{
public:
    void prepare (double sampleRateIn, float saHz, TanpuraTuning tuning = TanpuraTuning::PaSaSaSa,
                 float secondsBetweenPlucks = 1.2f);
    float renderNextSample();

private:
    static constexpr int kNumStrings = 4;

    std::array<KarplusStrongString, kNumStrings> strings;
    std::array<float, kNumStrings> stringFrequencies {};
    double sampleRate = 0.0;
    double samplesPerPluck = 0.0;
    double samplesSinceLastPluck = 0.0;
    int nextStringIndex = 0;
    bool prepared = false;
};
```

```cpp
// src/audio/tanpura/TanpuraSynth.cpp
#include "TanpuraSynth.h"
#include <cmath>

namespace
{
    float centsToFrequency (float saHz, float cents)
    {
        return saHz * std::pow (2.0f, cents / 1200.0f);
    }
}

void TanpuraSynth::prepare (double sampleRateIn, float saHz, TanpuraTuning tuning, float secondsBetweenPlucks)
{
    sampleRate = sampleRateIn;
    samplesPerPluck = sampleRate * (double) secondsBetweenPlucks;
    samplesSinceLastPluck = 0.0;
    nextStringIndex = 0;

    const float firstStringCents = (tuning == TanpuraTuning::PaSaSaSa) ? -500.0f : -700.0f;
    stringFrequencies[0] = centsToFrequency (saHz, firstStringCents); // Pa or Ma, mandra
    stringFrequencies[1] = centsToFrequency (saHz, -1200.0f);         // Sa, mandra
    stringFrequencies[2] = centsToFrequency (saHz, 0.0f);             // Sa, madhya
    stringFrequencies[3] = centsToFrequency (saHz, 0.0f);             // Sa, madhya

    prepared = true;
}

float TanpuraSynth::renderNextSample()
{
    if (! prepared)
        return 0.0f;

    if (samplesSinceLastPluck <= 0.0)
    {
        strings[(size_t) nextStringIndex].pluck (stringFrequencies[(size_t) nextStringIndex], sampleRate);
        nextStringIndex = (nextStringIndex + 1) % kNumStrings;
        samplesSinceLastPluck = samplesPerPluck;
    }
    samplesSinceLastPluck -= 1.0;

    float mixed = 0.0f;
    for (auto& s : strings)
        mixed += s.renderNextSample();

    return mixed / (float) kNumStrings;
}
```

```cpp
// src/audio/tanpura/TanpuraAudioSource.h
#pragma once
#include "TanpuraSynth.h"
#include <juce_audio_basics/juce_audio_basics.h>
#include <atomic>

class TanpuraAudioSource : public juce::AudioSource
{
public:
    void setSa (float saHz, TanpuraTuning tuning = TanpuraTuning::PaSaSaSa);
    void setGain (float newGain);
    void setEnabled (bool shouldBeEnabled);

    void prepareToPlay (int samplesPerBlockExpected, double sampleRate) override;
    void releaseResources() override;
    void getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill) override;

private:
    TanpuraSynth synth; // only ever touched on the audio thread (getNextAudioBlock and the retune it consumes)

    double sampleRate = 44100.0;

    // UI-thread-writable, audio-thread-readable. retunePending is the only
    // one that needs exchange() semantics - gain/enabled are simple values
    // read fresh every block, no "consume once" requirement.
    std::atomic<float> pendingSaHz { 220.0f };
    std::atomic<TanpuraTuning> pendingTuning { TanpuraTuning::PaSaSaSa };
    std::atomic<bool> retunePending { false };
    std::atomic<float> gain { 0.5f };
    std::atomic<bool> enabled { false };
};
```

```cpp
// src/audio/tanpura/TanpuraAudioSource.cpp
#include "TanpuraAudioSource.h"

void TanpuraAudioSource::setSa (float saHz, TanpuraTuning tuning)
{
    pendingSaHz = saHz;
    pendingTuning = tuning;
    retunePending = true;
}

void TanpuraAudioSource::setGain (float newGain)
{
    gain = juce::jlimit (0.0f, 1.0f, newGain);
}

void TanpuraAudioSource::setEnabled (bool shouldBeEnabled)
{
    enabled = shouldBeEnabled;
}

void TanpuraAudioSource::prepareToPlay (int /*samplesPerBlockExpected*/, double sampleRateIn)
{
    sampleRate = sampleRateIn;
    retunePending = true; // force an initial prepare() on the audio thread using whatever Sa is pending
}

void TanpuraAudioSource::releaseResources()
{
}

void TanpuraAudioSource::getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill)
{
    if (retunePending.exchange (false))
        synth.prepare (sampleRate, pendingSaHz.load(), pendingTuning.load());

    if (! enabled.load())
    {
        bufferToFill.clearActiveBufferRegion();
        return;
    }

    const float currentGain = gain.load();
    auto* buffer = bufferToFill.buffer;
    const int numChannels = buffer->getNumChannels();

    for (int i = 0; i < bufferToFill.numSamples; ++i)
    {
        const float sample = synth.renderNextSample() * currentGain;
        for (int ch = 0; ch < numChannels; ++ch)
            buffer->setSample (ch, bufferToFill.startSample + i, sample);
    }
}
```

**This is the critical part.** Replace `getNextAudioBlock()`'s body with:

```cpp
void MainComponent::getNextAudioBlock (const juce::AudioSourceChannelInfo& bufferToFill)
{
    // With 1 input channel and 2 output channels, JUCE's AudioSourcePlayer
    // aliases channel 0 of this buffer onto output channel 0's own memory,
    // PRE-FILLED with a copy of the mic input (verified against
    // juce_AudioSourcePlayer.cpp's channel-compaction logic: when
    // numInputs <= numOutputs, input channels are memcpy'd directly into
    // the corresponding output channels' memory before this callback runs).
    // Read the mic samples out FIRST - before anything below overwrites
    // this buffer - or the raw mic signal gets echoed straight back out to
    // the speakers, a real feedback risk with a mic and speakers in the
    // same room, not just a correctness bug.
    if (worker != nullptr && bufferToFill.buffer != nullptr && bufferToFill.buffer->getNumChannels() > 0)
    {
        const float* micChannel = bufferToFill.buffer->getReadPointer (0, bufferToFill.startSample);
        worker->pushAudio (micChannel, bufferToFill.numSamples);
    }

    tanpuraSource.getNextAudioBlock (bufferToFill);
}
```

(`tanpuraSource.getNextAudioBlock()` already clears the buffer when disabled, per Task 3's implementation - no separate `clearActiveBufferRegion()` call is needed here since the tanpura source's own `getNextAudioBlock` always either clears or fully overwrites every sample of the buffer.)

## Not covered by this plan (separate work / your own listening test)

- **You need to actually listen to it** - does the synthesized tanpura sound acceptable, is the volume slider responsive, does starting it on calibration feel right. This plan cannot verify any of that.
- Mic-bleed detection (checking whether the tanpura is leaking into the mic input and warning the user) - flagged as a nice-to-have in the original eng-review's Architecture decision, deferred here given the architectural fix in Task 4 already prevents the *software* mixing path from ever routing tanpura into the mic signal; the remaining risk is purely acoustic (speaker sound physically reaching the mic), which headphone use eliminates. Noting in `TODOS.md` rather than building now.
- Pan control - the original spec mentions "volume/pan controls"; this plan adds volume only. For a synthesized mono tanpura played through stereo output, pan has limited value without a richer stereo image (e.g. spreading the 4 strings across the stereo field), which is a real enhancement worth a future pass, not this one.
- Metronome/taal engine, packaging - unchanged, still the next pieces after this.
